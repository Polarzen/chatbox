# 0.1.18 · 在 Redmi 上接续 Windows 已有会话

Polarzen 只需为一个 Windows 档案配对一次。手机此后可打开该档案里的不同会话，也能看到电脑后来新增的会话。旧问答从 Windows Chatbox 本地历史导入；导入、翻页或刷新都不会重新请求模型生成回复。

## 从 0.1.17 升级

1. 做现场验收时，先按下方 **A** 在旧版电脑上准备测试记录。核对同批 APK、MSI、共享服务 ZIP 与交付的 SHA-256。
2. 正常停止旧共享服务。备份原数据目录（含 SQLite 数据库及同目录的辅助文件）和现用的代理配置。将新版服务 ZIP 解压到新目录。在该目录打开 PowerShell，输入原数据库的绝对路径，用原来的上游密钥启动。若此前自定义了监听端口，沿用原启动选项。

   ```powershell
   $db = (Resolve-Path -LiteralPath (Read-Host '原共享服务 SQLite 文件的完整路径')).Path
   python .\service.py --db "$db" serve
   ```

   `serve` 自动在旧库上迁移，重复启动可继续使用原数据。已有数据库跳过 `init`。手机沿用证书受信的 HTTPS 入口；使用临时隧道时，按下方“临时隧道与管理恢复”限制方法和路径。首次部署可参考旧指南的初始化和证书步骤，档案创建码按下节生成。[共享服务与 HTTPS 配置](SHARED_CHAT_GUIDE.md)
3. 退出 Windows Chatbox，运行 `Chatbox-0.1.18.msi` 并沿用原目录。将同签名的 0.1.18 APK 放在 Redmi 的 `/sdcard/chatbox/`，点该 APK 覆盖安装。若系统提示签名不兼容，保留现有安装和数据，使用与旧版签名匹配的包。升级后「此手机」仍是本机历史、草稿和附件的入口，原有单会话共享仍可使用。

## PC 授权一次，手机打开任一段

1. 在 Windows「连接设置」选择并验证目标 **AstrBot 服务档案**。这里的基础地址必须对应原聊天实际使用的 AstrBot 实例。在新版共享服务目录打开第二个 PowerShell 窗口，为同一个数据库生成有效期十分钟的**档案创建码**：

   ```powershell
   $db = (Resolve-Path -LiteralPath (Read-Host '同一个 SQLite 文件的完整路径')).Path
   python .\service.py --db "$db" profile-bootstrap
   ```

2. 在「连接设置」点「与手机共享此档案的会话」，核对档案名、现有会话数及今后新增会话的共享范围。在「共享服务地址」填 **PC 本机的共享服务回环地址**（默认 `http://127.0.0.1:8765`）。PC 的档案管理和目录发布均走本机入口。输入刚生成的档案创建码，点「确认共享此档案」，再点「生成一次性邀请码」。首次授权时选择并验证目标档案。此后只要 Windows Chatbox 运行且能连接共享服务，各已授权档案会独立在后台同步。切换到另一档案后，原档案仍可发布目录和问答。
3. 在 Redmi 打开「最近对话 → 来自电脑」，填写**手机可访问且证书受信的共享服务 HTTPS 地址**，输入电脑界面生成的**一次性档案配对码**，点「配对档案」。手机上的 `127.0.0.1` 指向手机本身。旧版单房间码只授权原房间。
4. 核对「来源档案」和首次同步进度。列表按最近活动排序；可按标题搜索或点「加载更多会话」。同名项可分别打开查看正文；长历史可点「加载更早的记录」。在会话页底部输入文字并发送，回到 Windows **同一原会话的普通输入框**即可看到新问答并继续回复。在手机点「返回」换另一段，重启后配对仍有效。需要确认新改名或新会话时，可在两端的档案面板点「立即同步」。

## 临时隧道与管理恢复

使用临时公网隧道时，只放行下表中的五组 HTTP 方法和完整路径。其他路径或方法一律返回 404。手机凭一次性档案邀请码配对；PC 的创建、邀请、设备管理、恢复和历史发布走共享服务的本机地址。包内 Caddyfile 供受信局域网部署，公网隧道需另设这五条规则。

| 手机操作 | HTTP 方法 | 完整路径 |
| --- | --- | --- |
| 配对 | POST | `/v1/profile/join` |
| 会话目录 | GET | `/v1/profile/sessions` |
| 分页读取轮次 | GET | `/v1/profile/turns` |
| 核对单轮状态 | GET | `/v1/profile/turn` |
| 在原会话续聊 | POST | `/v1/profile/send` |

若 Windows 提示档案主人凭据失效或无法读取，在原共享服务主机对原数据库运行以下命令，核对档案编号后签发一次性主人恢复码。

```powershell
python .\service.py --db "$db" profiles
$profileId = Read-Host '上一步列出的原档案编号'
python .\service.py --db "$db" profile-recover --profile "$profileId"
```

在原 Windows 档案中重新验证 AstrBot，打开「与手机共享此档案的会话」，填写本机共享服务地址。若显示「档案主人恢复码」，输入刚签发的码并点「恢复此档案主人授权」。若此前创建了档案但本机未保存主人凭据，在「档案创建码或原档案主人恢复码」处输入该码，点「确认共享此档案」。恢复码十分钟内有效，只能用一次。该码只能恢复原档案的主人授权；成功后旧主人凭据和未用邀请码失效，已配对手机及原有会话继续可用。密钥和一次性码仅在本机交互输入，不写进验收记录。

## 在线条件与数据范围

| 操作 | 哪一端需要在线 |
| --- | --- |
| 首次发布旧历史，或发布新会话、改名、删除 | Windows Chatbox 正在运行且能连接共享服务。各已授权档案在后台独立同步。首次授权须先验证实际 AstrBot 档案；服务核对原会话身份后才允许续聊。 |
| 浏览已发布的目录或未缓存的正文 | 手机能连接 HTTPS 入口及共享服务即可。断网时可阅读本机已缓存的目录和正文，查看上次同步时间。 |
| 从手机续聊 | HTTPS 入口、共享服务、原 AstrBot 及模型可用。已经发布并可续聊的会话无需保持 Windows Chatbox 窗口打开。如果共享服务部署在 PC，该主机仍要运行。 |
| 在 Windows 看到手机的新轮次，或从原输入框回复 | Windows Chatbox 在线时按档案同步写回；要查看或回复，回到该档案的原会话。PC 发送时还需原 AstrBot 和模型可用；手机回前台或重连后补齐。 |

档案共享支持双向文字。附件只展示旧记录保存的类型或提示，原图、语音文件仍在原设备。会话身份失效、原房间无法核对或旧记录尚未完整导入时，按页面提示查看已导入的历史。PC 只剩标题、未保存或已删除的旧正文无法从 AstrBot 的会话列表补回。发送结果未知时先等待核对，出现「按原编号重试」再使用该按钮。

「会话操作 → 在此手机隐藏」只改这台手机的列表，可从「档案操作 → 查看本机已隐藏」恢复。PC 删除会话并同步后，它会移出手机目录，共享服务按原房间规则保留已有历史。在 Windows 档案面板选设备并「撤销授权」，服务立即拒绝该设备的新读取和发送。离线手机在下次联系服务得知撤销后，清除该档案的绑定及缓存。

## Polarzen 的 A/B 验收

**A · 先造历史，再配对。** 在 0.1.17 的测试档案 A 准备三段会话，各有旧问答。两段设为同名，正文不同；其中一段用自己选的唯一短句与 AstrBot 完成一轮。另在测试档案 B 建一段。记下四段的标题、轮数和用于辨认的正文。升级后只配对 A 一次，在 Windows 档案 A 新建一段有测试文字的会话并切换到 B；保持电脑在线，在手机刷新确认 A 的新增会话出现。再从「来自电脑」逐一打开原有三段，核对配对前的问题和完整回复。搜索同名标题应有两项，档案 B 的标题应搜不到。

**B · 两端各续一轮。** 在手机打开含唯一短句的原会话并追问。核对回复能接续该短句、AstrBot 记录采用原用户及会话、PC 原会话只增加一轮。再在 PC 同一输入框发一条新的文字，核对手机出现同一问答且顺序一致。主动连发两次相同文字应各占一轮；随后仅刷新、翻页或重开，轮数和生成次数应保持不变。

在本地验收记录中写下包的 SHA-256、时间、A/B 各端预期和实际轮数，以及通过结果或第一个不符的步骤。若做了主人授权恢复，补记原档案是否能继续同步、原手机是否仍能打开同一段会话。归档使用测试档案代号，省略密钥、邀请码、恢复码和真实聊天正文。
