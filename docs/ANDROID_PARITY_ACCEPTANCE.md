## 安装包跨端实测

在 Windows 从本地 MSI 实际解包并启动客户端，使用隔离档案；Android 通过受信 HTTPS 从正常界面用一次性码加入。第一轮 PC 发送「本轮代号是青松47」，回答「记住了。」。手机追问 `QA-RECALL` 得到「青松47」，Windows 界面自动出现这一轮。移除模拟器测试端口映射后，手机报告无法连接；此期间 PC 从输入框发送「离线第一轮：松针。」及「离线第二轮：松果。」。恢复连通后手机自动补齐，两次刷新仍是四轮，顺序一致。AstrBot 实际历史中的八条消息与两端逐字匹配。[Windows 四轮界面](parity-017/paired-windows.png) · [Android 四轮界面](parity-017/paired-android.png)

上述四轮的 Windows MSI 摘要前八位为 `c736e276`，Android 为 `d6dbda88`。交付 MSI `0f58455b` 已单独解包，启动后在原隔离档案恢复同一绑定及四轮历史；从窗口发送第五轮 `QA-RECALL5`，得到「青松47」，AstrBot 实际历史核对为五问五答，最终 Android APK `83603683` 在原绑定中显示相同的第五轮和「已同步」。受控模型计数为 5 次正文生成和 1 次自动标题。[最终 APK 界面](parity-017/final-pair.png)交付 MSI 解包的 Chatbox.exe 以 `--smoke-test` 启动，退出码 0，并写入 `chatbox-smoke-ok`。此机器的隔离窗口首次启动时 Direct3D 初始化停滞，实测窗口使用进程内软件渲染设置；日常 Windows 配置未改动。

## Android 系统入口

后台完成会产生通用通知。保留通知并终止应用进程后，实际点通知可返回原档案、原会话的 70 行回复；删除目标后再点旧通知，当前有效会话不变。关闭开关后又完成一次后台回复，系统未显示 Chatbox 通知。下载期间撤销提示资格与媒体继续缓存另由自动化覆盖。Android 13 以上的通知授权弹窗和 HyperOS 后台策略仍需 Redmi 现场验证。[通知冷启动回跳](parity-017/notification-return.png)

从系统图库分享图片时，需先确认目标，应用只添加草稿。在此前的 `d6dbda88` 构建中，原先打开的会话抽屉曾遮住新草稿。交付 APK `83603683` 修复了从外部入口打开聊天时残留的抽屉和搜索面板。此 APK 已在同一模拟器覆盖安装，保留服务和已发送历史，重新运行设备端历史测试通过。实测在原抽屉打开时从图库分享，确认目标后直接看到图片和目标草稿，冷启动后仍在。此前开着抽屉时再从通知进入，分别用热启动和冷启动定位原轮，均收起了抽屉。用带临时读取授权的系统剪贴板 URI 粘贴图片，可进入草稿。撤销原 URI 的访问后再次导入得到提示，先前缓存到本机的草稿图片仍可打开。另从界面使用仅有 chat 的命名 Key 尝试上传，收到缺少 file 权限的提示。创建端在横竖屏间切换后保持同一有效邀请码，可正常撤销。

## Android 8 系统键盘、会话菜单与通知补验

在 API 26 模拟器安装最终 APK `83603683`，通过 9 项补验。外接键盘事件中，Shift+Enter 在光标处换行，Enter 提交两行文字并收到 SSE 回复。输入法仍有有效组字区间时，Enter 保留草稿，测试服务未收到请求。带 Ctrl 修饰键的 Android 键盘事件触发 Ctrl+K 搜索。长按回复可选择、复制单词。会话改名后重开仍保留，可恢复默认名；取消删除保留会话，确认删除才移除。纯语音草稿移除后清空，重录后只有一段新的录音。

在 Android 系统设置关闭 Chatbox 通知，应用自己的开关保持开启并显示「系统通知已关闭」。应用退到后台后回复完成，通知栏未出现提醒；恢复系统权限再发一轮，通知栏出现通用回复提醒。收发使用隔离 HTTPS 测试服务。此轮只覆盖 Android 8 的系统通知开关；Android 16 运行时授权和 HyperOS 后台策略仍待真机验收。
