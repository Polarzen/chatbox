# Chatbox 0.1.21 候选版升级与双端复验

本分支从正式版 0.1.19 开发聊天窗口与会话上下文。0.1.20 手环原型独立维护。正在使用原型并需要其手环功能时，请保留原安装，在独立环境试用候选版。以下为 Polarzen 在 Windows 和 Redmi Turbo 3 的操作清单，测试结果另见同批交付记录。

## 从 0.1.19 覆盖升级

1. 在原会话记下标题和一条可搜索的旧消息，留下简短草稿。待发送任务结束后，正常停止正在运行的共享服务，退出 Windows Chatbox（含托盘），备份 `%LOCALAPPDATA%\Chatbox`；独立部署还需备份原共享数据库目录和代理配置。手机上另存重要正文和附件，保留原安装及应用数据。[设备同步与备份指南](DEVICE_SYNC_GUIDE.md)
2. 在同批交付目录用 PowerShell 执行 `Get-FileHash .\*.msi, .\*.apk -Algorithm SHA256`，将两个结果分别与交付校验清单比对。Windows 运行候选 MSI，沿用原目录；Redmi 打开同签名候选 APK，选系统的更新安装。若系统报告签名不匹配，保留原应用并取得与原签名匹配的安装包。
3. 在电脑启动原 AstrBot、共享服务及原 HTTPS 入口，检查手机连接。沿用原配对，先用「跟随服务默认」续聊。常规聊天使用原 AstrBot 接口；只有要测试自选历史时，才由服务维护者在匹配的 **AstrBot 4.29.4** 上按配套说明安装适配，再从会话菜单核对能力。服务未提供自选能力时，继续使用默认模式。[4.29.4 适配补丁](../integrations/patches/astrbot-v4.29.4-chatbox-context.patch) · [配对与恢复](DEVICE_SYNC_GUIDE.md)

## 发送前怎样看上下文

| 在哪里看 | 代表什么 |
| --- | --- |
| 聊天窗口、搜索 | 这里是保存下来的聊天历史。减少轮数或取消固定后仍可搜索、回看。 |
| 会话菜单 → 上下文 | 跟随服务默认时，由 AstrBot 管理历史。自选时，一轮是一个问题与它的回复。可按发言方单独固定某轮的提问或回复；与最近 N 轮重合的同一条只计一次。切回默认并保存会解除固定。 |
| 发送前预览、最终模型请求 | 自选预览列出供下一次生成参考的历史及当前问题。模型窗口还要容纳系统指令、工具结构及生成所需空间。轮数不能换算为准确占用比例；估算仅作参考。遇到容量限制时，按提示缩小范围、取消固定或另开会话。 |

## Polarzen 最短复验清单

1. **旧聊天与截图。** 双端重开，核对上次会话、旧消息、原机草稿。用同一段示例对话，在 Windows 常规窗、窄窗和 Redmi 竖屏分别截图聊天主窗、展开的最近对话、上下文选择和提醒，保留对应的初版图供对照。电脑用键盘打开最近对话、固定再收起；窄窗与手机选择会话后，核对正文宽度、输入框及焦点。
2. **名字与同步。** 在「修改对方名称」先设档案默认名，再为一个会话设置覆盖名；看预览、旧气泡和另一端的顶栏，同档案另一会话应沿用默认名。用原会话标题搜索定位。清空覆盖名并保存，应恢复档案名；试重名和超长输入。断开手机网络，两端为同一会话填写不同名字，重连后核对冲突提示、选定名称再保存；两端重开核对同一结果。自选上下文的轮数也用同样方法检查冲突。
3. **消息操作。** 在消息的桌面菜单或手机长按菜单复制正文。用隔离会话制造一次明确的发送失败，恢复连接后从原消息重试一次。分别在来源设备发送图片和 WAV 并核对回放、多行中文草稿、手机键盘开合。流式回复时上翻，核对阅读位置保持，点「回到最新」返回末尾。
4. **实际入模。** 在有适配的隔离会话中，首轮录入标记 `留松塔`，第二轮录入 `舍海盐`，让两轮分别回复“甲轮结束”和“乙轮结束”；第三轮发普通问答。固定第一轮的**提问**，选最近一轮。发送一条不含标记的新问题前，在两端核对同样的选择。检查这次到模型提供方的最终请求：两处旧标记只出现“留松塔”，角色是用户；第一轮回复未随提问固定，第三轮问答及当前问题各一次，系统指令保留。若样本含工具调用，还要核对调用与结果配对。确认这次普通发送只生成一次。扩大 N 后再发，核对“舍海盐”重新进入，重合的固定消息只出现一次；改为只固定旧回复，将 N 缩回一轮，再核对“甲轮结束”为助手消息，原提问“留松塔”已排除。仅看到预览或模型复述时，将最终请求标记为待核实。
5. **提示与恢复。** 设一个即将达到的自设轮数，跨过阈值后核对提醒原因。选稍后处理，再切换设备、重开应用，观察同一阈值是否重复提示。另用可复现的容量受限案例核对发送前提示与调整选项。保留原会话未发草稿，滚到旧消息，先取消「新开会话」，再确认新开；返回原会话，核对草稿和阅读位置。分别记录真实模型、模拟服务、模拟器和实际设备的观察结果。
