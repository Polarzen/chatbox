# 0.1.20 手环历史数据原型配置与复验指南

0.1.20 原型已暂停，真实来源全自动验收尚未通过。正式下载沿用 [v0.1.19 稳定版](https://github.com/Polarzen/chatbox/releases/tag/v0.1.19)。以下步骤供复验候选构建时使用。

恢复开发须先验证系统数据源能自动提供真实记录，或获得官方接入批准。优先核对睡眠，其次是步数和全天历史心率。候选构建沿用原电脑配对和手环绑定。核对来源记录后，可在原会话查询，并分别配置运动总结与晨间摘要的提醒开关。

小米官方云端接口列有睡眠（`200009`）、步数（`200016`）和心率（`200007`），须按接入流程获批后再开发和验证。[云端接口指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2333) · [接入流程](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2326)

## 候选构建覆盖安装

1. 在同一交付目录运行 `Get-ChildItem -File -Include *.apk,*.msi,*.zip -Path .\* | Get-FileHash -Algorithm SHA256`，逐项比对随包 `SHA256SUMS.txt`。使用同批 APK、MSI 和 Chatbox 手环插件 ZIP。MSI 含配套共享服务。
2. Windows 如果正在运行托管共享服务，先在原设备设置点「停止共享」，等当前请求结束，再退出 Chatbox 和托盘。记下原自启选项，备份本地历史、原共享数据库及同目录辅助文件。沿用原目录安装 MSI，回设备设置点「启动服务」「检查入口」。原先使用登录自启的，重新勾选「Windows 登录后自动恢复共享服务」。已有配对继续使用。独立部署者先停旧进程，使用同批共享服务文件、原数据库及原受限 HTTPS 代理。[设备连接与恢复](DEVICE_SYNC_GUIDE.md)
3. Android 在文件管理器点开 APK 覆盖安装。已有 Chatbox 需要相同应用签名。系统报告签名不兼容时保留现有安装和数据，换用匹配签名的包。手机从「最近对话 → 设备设置」检查原电脑连接。
4. Windows 服务需要 Python 3.10+ 和手机使用的 IANA 时区。可在 PowerShell 把 `$svcPython` 设为共享服务所用的 `python.exe` 完整路径，然后运行下方命令。如果出现 `ZoneInfoNotFoundError`，用 `& $svcPython -m pip install tzdata` 安装到该解释器环境，再用同一命令复查并重启服务。服务以 `-E -s` 启动，用户级包目录不会加载。

   ```powershell
   & $svcPython -E -s -c "from zoneinfo import ZoneInfo; print(ZoneInfo('Asia/Hong_Kong'))"
   ```

## 首次授权和插件配置

1. 打开小米运动健康，让手环同步。记下昨晚睡眠或一项已结束运动的时间和时区。在小米运动健康的第三方数据共享设置中查找 Health Connect，并在系统「健康数据共享」核对该应用的写入权限、数据类别和记录来源。入口随地区和版本变化。小米应用里有记录而系统无对应记录时，将该指标记为缺失。[小米运动健康共享说明](https://support.google.com/googlehealth/answer/14236613?hl=zh-Hans-CN) · [Health Connect 读取记录](https://developer.android.com/health-and-fitness/health-connect/read-data)
2. 手机打开「最近对话 → 设备设置 → 手环数据」，只打开要共享的指标，逐项完成系统授权。查运动心率时同时允许「运动」和「运动期间心率」。距离是可单独拒绝的权限。在「小米运动健康来源包名」选择与手机应用一致的包名。页面按最近 30 天的授权记录标记「已读到记录」或「尚未读到记录」。后者也可保存，等下一次小米同步后再看。
3. 选「允许查询的个人档案」。档案须由该手机建立、属于同一主人并已同步到电脑。如果列表为空，先在「本机服务档案与密钥」连接自己的 AstrBot，并同步档案。按需打开「处理新完成的运动」和「晨间查询昨晚睡眠」。晨间填写手机本地时间和等待分钟数（1–1440）。只查询时可以留空「个人会话」。要推送时打开「发送运动总结」或「发送晨间摘要」，再从已完成过对话的会话中选择接收者。点「保存共享设置」，等「最近成功同步」更新。
4. 确认电脑在线且已收到共享设置，再在本页点「生成或更换 AstrBot 插件凭据」。将仅显示一次的 `plugin_token` 填入下一步的插件私有配置，勿发到聊天或截图。再次生成会立即废止旧令牌。更换绑定来源或档案后重新生成。
5. 在**该档案实际连接的 AstrBot**（目标版本 4.29.4）打开 WebUI「插件 → 安装插件 → 从文件安装」，上传同批手环插件 ZIP。启用「Chatbox 手环数据」，其插件名为 `astrbot_plugin_chatbox_wearable`。配置 `service_url` 为手机显示的受限 HTTPS 地址，仅填协议、主机和可选端口。同机 AstrBot 也可用受限网关 `http://127.0.0.1:18766`（改过端口时用实际值）。填入 `plugin_token` 后保存并重载插件。此处需要的是健康查询令牌，设备配对码和 AstrBot OpenAPI Key 各有独立用途。
6. 在 AstrBot 的函数工具管理中找到并启用 `query_wearable_data`。目标档案、人格及模型须允许此插件并支持工具调用。在组件的工具权限中允许该用户所属角色调用此工具。4.29.4 的插件工具缺省为 `member`。若设为 `admin`，普通成员将收到权限拒绝。健康权限仍由 Chatbox 服务逐次核对。日常聊天保留原来的输入框和个人账号。

## 数据流、时效与撤销

- **历史来源。** 手环 → 小米运动健康 → 本机 Health Connect → 已配对的手机 Chatbox → 受限 HTTPS 网关 → 电脑共享服务 SQLite。手机只核对已选来源及指标，按记录标识和版本同步新增、修订与删除。首次历史导入抑制运动事件。来源包名为 `com.xiaomi.wearable` 或 `com.mi.health`。仅包名不足以证明具体手环型号。核对查询结果的 `reportedDevices`（类型、厂商和型号，以来源实际提供为准）及小米应用中同一时段的记录。缺设备信息时标为「设备未确认」。Chatbox 排除明确标注为手动输入或手机设备的记录。
- **聊天查询。** 模型按需要调用工具，插件从正在进行的 WebChat 私聊事件取得主人、会话和请求标识。服务核对手机、来源档案和当前共享会话。调用参数只选指标、时间和粒度。默认返回摘要。明确要求分期或样本时可返回受限明细。单次查询最长 30 天，默认明细最多 32 条。工具结果可能进入个人档案所配模型的上下文及 AstrBot 的历史或日志。
- **主动查询。** AstrBot 官方 basic cron 每分钟轮询。共享服务按新运动 ID、晨间本地日期持久化处理状态。晨间在等待窗口内重查，超窗跳过。关闭对应提醒时，任务仍查询并静默完成。打开提醒时，服务再次核对选定个人会话，将一条只有助手正文的消息写入 Chatbox 共享历史，两端照常同步。AstrBot WebChat 本身支持主动消息，但有独立的历史存储。本插件把投递写入 Chatbox 会话。目的地失效时不会改投其他聊天。[AstrBot 4.29.4 的 cron 接口](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/cron/manager.py) · [WebChat 主动消息实现](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/platform/sources/webchat/webchat_adapter.py)
- **离线与过期。** 查询结果包含来源包、单位、查询及观测覆盖时间、样本数、测量时间 `measuredAtMs` 和最近同步 `lastSyncMs`（Unix 毫秒）。45 分钟没有同步联系会标作推断离线，参考 `lastContactMs`。指标成功同步距今满 24 小时标为 `stale`。仍可返回在保留期内的旧数据。连同 `dataStatus` 解读真实零、无记录、部分覆盖、无权限和来源不可用。
- **保留和删除。** 共享健康记录到测量区间结束后 30 天即不再可查，服务在后续同步或插件访问时清理。任务状态按计划时间保留 30 天。手机「清除已同步健康缓存」会清空电脑的健康记录和任务并从清理时间继续采集。要关闭其中一项，取消该指标并保存，也可在系统撤销该项权限。「停止共享」撤销全部健康授权。离线时以电脑收到撤销为生效点，恢复连接后优先对账。需立即吊销离线手机时，在电脑设备设置中「撤销」该设备。已经发出的摘要属于聊天历史，要按原会话的删除范围另行处理。原始小米和 Health Connect 记录由各自应用管理。
- **HyperOS 后台。** 系统支持时，在 Chatbox 手环页点「允许在后台读取」。保持电脑唤醒、共享服务与 AstrBot 在线，手机可达 HTTPS 入口、小米运动健康能同步。Android 向系统申请有网络时约 15 分钟一次的任务，锁屏、省电和后台限制会影响实际触发时间。先按当前系统设置实测。若只在打开 Chatbox 后补齐，再检查两款应用的后台运行和省电设置，按需调整并重测，记录差异。缺少后台权限时，回前台可补齐。

v0.1.19 的聊天页「心率」仍走蓝牙心率广播，发送普通消息时可附带最近 10 秒内的有效 BPM 和接收时间。断开或过期后停止附带。历史运动心率只取相应运动时段和来源的 Health Connect 样本。

## 实机复验

恢复复验时，在本机记录 Redmi Turbo 3 的 Android 16 / HyperOS 3 完整版本、小米运动健康版本及包名、手环 9 固件、Chatbox 与 AstrBot 版本、时区、权限和省电设置。在本机填写下表。核对数据和复验实测记录留在本地，仓库仅记录软件验证范围。请勿提交个人原始记录、令牌或带正文的会话日志。

| A · 在小米运动健康与 Chatbox 对照同一时段 | 应核对的字段和单位 | 现场结果 |
| --- | --- | --- |
| 今日步数 | 本地零点起的步数（步）、来源和覆盖区间。另有手机来源时只计所选来源。重叠或跨边界而无法拆分的区间应给出部分覆盖。 | 待验 |
| 昨晚睡眠 | 核对主夜间记录与午睡、跨午夜时间。分别查记录开始/结束、首个入睡/末个睡眠段结束、卧床区间和实际睡眠秒数。按实际字段对照浅睡、深睡、REM、清醒及缺失段。分期不完整时总睡眠可为空。 | 待验 |
| 最近运动 | 核对类型、开始/结束和时区、时长（秒）、距离（米）。距离只在同来源距离记录完整覆盖该运动时返回。缺少心率仍可有运动时长。 | 待验 |
| 运动期间心率 | 同一来源、运动起点至终点前的样本，核对数量、首末样本时间、最低/最高/算术平均 BPM。相同时间相同值去重，同一时间冲突值排除。记录小米应用展示口径及差异。 | 待验 |

每项在本地填写「来源包及设备证据 / 有数据的字段 / 缺失字段 / 单位 / 样本数 / 两边起止时间差 / 通过或原因」。若小米未写入某字段，核对该版本允许的官方共享或导出途径。导出文件只可作为注明数据日期的人工对照，本版自动路径以 Health Connect 为准。

| --- | --- | --- |
| B · 聊天 | 在两端共享目录中的原个人会话输入「今天训练完有点累」。核对真实工具调用名、来源、时间、返回值与最终回复。模型应自行选择工具且无需逐次确认。再用群聊、其他主人或未授权档案验证拒绝。模型未发出工具调用则记录未通过。 | 待验 |

| D · 晨间、离线和撤权 | 将晨间任务设到临近的本地时间，分别验证无记录等待、窗口内补齐、超窗、重复触发。同一日期只运行一次，独立日期可分别测试静默和两端可见的同一条消息。手机断网后在电脑查询，核对缓存时间。恢复后应更新。依次核验单项撤权、清缓存、目的地删除和电脑撤销设备。 | 待验 |

**C、D 的本地计时单**（带日期和 UTC 偏移，能观察到的每一项填实测值）。手环运动结束／晨间计划时间 **待验**。小米同步完成 **待验**。手机锁屏及后台条件 **待验**。共享服务收件 **待验**。插件查询 **待验**。目标会话投递 **待验**。Windows 与 Android 首次可见 **待验**。一次观察只能确定上下限时写下观察区间，不能用 15 分钟周期或 1 分钟轮询推算实测时间。

静默结果可在 PC 上用只读 SQLite 查看共享服务的 `wearable_jobs`。库路径见 `%LOCALAPPDATA%\Polarzen\Chatbox\device-runtime\config.json` 的 `dbPath`。在测试前后执行 `SELECT kind,state,COUNT(*) FROM wearable_jobs GROUP BY kind,state;`，对照 `silent`、`delivered`、`expired` 的计数变化和目标会话消息数。需要验证等待时，在截止前和截止后各观察一次。终态计数只证明已完成的处理，精确的查询时刻需另有时间记录。

交付检查时分别记录固定样例、模拟器、真实 AstrBot 运行、Redmi 和真实手环的证据。SDK 编译、样例统计和模拟事件可验证对应的软件路径。只有同一项真实手环历史数据通过聊天自主查询、无新消息查询及提醒开关复验，方可判定本轮核心功能通过。
