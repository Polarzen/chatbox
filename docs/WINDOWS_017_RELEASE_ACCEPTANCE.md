## 托管 Windows 原目录升级

托管运行器先安装 [v0.1.5 正式发布的 MSI](https://github.com/Polarzen/chatbox/releases/tag/v0.1.5)，再以相同的 `INSTALLDIR` 安装候选版。开始菜单快捷方式指向已安装的 `Chatbox.exe`，该文件的版本为 0.1.7，SHA-256 与候选包中的 EXE 一致。通过开始菜单连续启动两次，原有 DPAPI 凭据仍可使用，测试会话和图片引用均保留。托管环境不支持本轮需要的交互式窗口操作。[构建及升级验证运行](https://github.com/Polarzen/chatbox/actions/runs/45112103783)

## 日常 Windows 窗口验收

升级前的基线取自日常机器已安装的 0.1.6。0.1.7 窗口加载了上述 CI MSI 通过 Windows Installer 管理安装方式解包得到的程序。日常机器的原目录升级在 UAC 确认阶段由 Windows 返回“操作已被用户取消”。随后核对安装目录中的 EXE，版本仍为 0.1.6。

### 滚动条与布局对照

两版载入同一份含 48 个会话的 QA 数据并选中同一会话。窗口均为 1000 × 760 dp。在 Windows 100% 缩放（96 DPI）下，截图为 1000 × 760 像素。在 150% 缩放（144 DPI）下，截图为 1500 × 1140 像素。表中每个宽度链接到对应的完整窗口截图。

| 缩放 | 0.1.6 常态 | 0.1.6 悬停 | 0.1.7 常态 | 0.1.7 悬停 |
|---|---:|---:|---:|---:|
| 100% | [16 px](windows-017/before-100-normal.png) | [16 px](windows-017/before-100-hover.png) | [4 px](windows-017/probe-100-normal.png) | [6 px](windows-017/probe-100-hover.png) |
| 150% | [24 px](windows-017/before-150-normal.png) | [24 px](windows-017/before-150-hover.png) | [6 px](windows-017/probe-150-normal.png) | [9 px](windows-017/probe-150-hover.png) |

候选版滑块常态为灰色 `#A49FAF`，悬停时加深为 `#797284`。0.1.6 为滚动控件单独留出 24 dp。0.1.7 将 14 dp 宽的鼠标操作区叠在列表边缘，额外布局占宽为 0 dp。对照相同缩放下的窗口，会话行末菜单向右移动 24 dp，右侧聊天正文区域逐像素一致。

### 候选程序的鼠标与会话操作

| 实际操作 | 观察结果 |
|---|---|
| 分别打开 0 条和 3 条会话的独立 QA 配置 | 空列表显示「还没有对话」。短列表的三条记录均可见，其中一条长标题换为两行。默认展开宽度下，两种列表均未显示滑块、轨道或上下按钮。 |
| 打开 12 条会话的独立 QA 配置 | 默认高度下可见第 1 至第 8 条，第 8 条仅部分可见，列表右侧出现细滑块。改变窗口高度时的显隐与稳定性仍待安装版复核。 |
| 从 14 dp 操作区靠外缘的位置拖动细滑块 | 滚至底部可见第 48 行，再拖回中段。当前聊天标题和 QA 草稿保持原样。 |
| 在中段点击第一条「中段同名会话」（第 25 行） | 选中行保持在原位置，正文显示对应的唯一回复「QA long 25 独立答复」。 |
| 点击该行的「⋯」并打开删除确认框 | 确认框与目标会话匹配。取消后原行仍在。 |
| 切回「验收 24」 | 该会话原有的混合草稿恢复。 |

### 既有双图拖放证据

0.1.6 验收时，用户现场确认从资源管理器拖入 PNG 和 JPEG 后同时出现两个预览，并使用中文输入法写入草稿。安装版计时和会话历史确认两张图片依次上传、同一条消息完成且有回复。真实资源管理器中 TXT 的拒绝提示当时仍待确认，文件名和拒绝原因只在模拟 AWT 拖放中观察到。本轮未新增发送请求。[0.1.6 验收记录](WINDOWS_016_RELEASE_ACCEPTANCE.md)
