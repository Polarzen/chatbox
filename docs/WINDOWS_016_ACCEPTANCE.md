本地交付目录为 `D:\Chatbox验收 V1\ui-redesign`。退出旧客户端，双击目录中的 `Chatbox-0.1.6.msi`，安装后从开始菜单打开 Chatbox。本次实机验收通过 Windows Installer 解包并启动随包的 `Chatbox.exe`，使用独立的当前用户测试数据目录。日常安装版及其凭据未参与升级测试。

## 真实 AstrBot 联机

- **本机日常 Launcher 实例**。客户端实际识别出同一实例，先后观察到回环端口 18794 和 15923。在 18794 上用随机无效测试凭据查询会话，客户端显示「聊天 API 密钥无效或已撤销」。本次没有用日常密钥发送验收消息。
- **独立的真实 AstrBot 4.29.4**。使用该版本自己的密钥服务创建临时聊天凭据，运行在隔离数据目录和回环端口 65346。打包客户端的传输代码调用会话接口，发送内置命令 `/sid`，收到包含测试会话 ID 和 `webchat` 的 SSE 回复。发送前后会话数从 0 变为 1。该实例已停止并清理。没有调用模型供应商。

## Windows 窗口与隔离服务

- 从安装包启动后，标题栏显示 `chatbox`。点击连接状态能进入设置，顶栏密钥菜单可直接切换。缩窄后侧栏自动收起，左上按钮能重新打开。原会话中的图片在重开后仍可见。
- Windows 窗口实测为 144 DPI（150% 缩放）。默认外窗为 1000 × 760 逻辑像素，客户区约为 985 × 723 逻辑像素。以实测客户区的 1477 × 1084 物理像素和同一缩放复现生产聊天布局，单行、无待发附件时，消息区高 850 物理像素，即 566.7 逻辑像素，占客户区高度的 **78.41%**。另用 JDK 17 直接运行随包的应用 JAR，读取实际布局边界，得到 851 / 1085 = **78.43%**。两组测量均计入滚动区域自身的内边距。
- 两个本地 HTTPS 服务模拟 AstrBot 的会话、聊天、文件上传和下载接口。测试只使用随机生成的凭据。0.1.5 格式的历史和单个 DPAPI 凭据可直接加载，迁移名称为「原有密钥」。在窗口中将其改名为「日常使用」，再新增「图片测试」并切换。第二配置最初显示「添加密钥」，添加「备用服务」后正常连接，重启恢复到该配置及其活动项。回到第一配置时恢复其独立的密钥列表。
- 实际从含空格和中文的目录选择 PNG 和 JPEG。通过发送按钮发送纯 PNG，通过 Enter 发送 JPEG 和说明；服务端的上传和聊天请求均返回 200，并回传了可显示的图片。重开能按会话回看。带延迟的测试消息在切换会话后完成，回复留在发起会话。
- Windows 拼音候选出现时，首次 Enter 将输入留在草稿中。Shift+Enter 插入一行，普通 Enter 将两行作为一条消息发出。测试还覆盖了以换行替换选中文本。
- 密钥管理中的「权限」说明当前凭据已经验证的聊天能力。当前 AstrBot 会话接口无法列出完整授权，用户可由这里打开本实例 WebUI 核查。对隔离历史、命名密钥元数据及服务请求日志的检查未发现完整测试凭据或其末八位。

## 升级、切换和会话回归

| 验收场景 | 操作和结果 |
|---|---|
| B · 旧版升级 | 用 0.1.5 格式的历史文件和当前 Windows 用户加密的测试凭据启动。旧会话可读，原有密钥能验证并改名。连续重开两次后仍只有一条密钥记录。 |
| C · 成功切换及候选验证失败 | 从顶栏菜单切换后，下一条聊天请求在服务端显示新密钥的别名。随后让测试服务拒绝另一个候选项，菜单在该项下显示无效提示，原活动项仍为「已连接」。再次发送，服务端确认使用上次成功验证的密钥。草稿在切换期间保留。 |
| D · 配置隔离与移除 | 分别在两个空配置中添加各自的密钥。在第二配置确认移除唯一的活动项后，其加密凭据随之删除。重开仍选中第二配置并显示待配置，切回第一配置可继续使用其原密钥。 |
| E · 聊天与附件 | 新建会话、发送并在流式回复过程中回看旧会话。服务端收到了新会话的 ID，回复和图片保存到该会话。通过 Windows 选图入口验证 PNG、JPEG 的选择、移除和发送。 |
