## 三轮文字、会话与耗时

服务为 Launcher 管理的 AstrBot 4.29.4。实例 UUID 前缀为 `8411fd3d`，服务端会话 UUID 前缀为 `77c07c16`，已按完整标识核对。五轮测试在服务端各有一条收件和一条回复，每对记录共享本轮请求标识。五轮对应的模型统计均记录 `deepseek-v4.1-flash-1017` 且调用完成。模型统计表没有请求外键，归属按会话、调用时间窗和该请求唯一成功的模型调用交叉匹配。

| 顺序 | 操作、预期与实际回答 | 点击后首次在窗口观察到正文 | 模型调用至首 token | 点击至本地写入完成 |
|---|---|---|---|---|
| 1 | 问「银杏站N48」四盒、每盒七张，另有三张散票。答出站名和 **31 张** | 20.0 秒时没有正文，22.5 秒时已有正文且仍在等待 | 1.72 秒 | 22.87 秒 |
| 2 | 完全退出再打开，追问上一轮的车站卖出九张后还剩多少。模型写出 **银杏站N48、22 张**，并给出分段故事说明 | 16.0 秒时没有正文，19.0 秒时可见部分正文且仍在等待 | 1.95 秒 | 20.29 秒 |
| 3 | 经 Launcher 正常重启后继续追问站名和余票。模型答出 **银杏站N48、22 张** | 25.0 秒采样未见正文，下次采样在 32.3 秒，已显示完整回答 | 1.68 秒 | 26.12 秒 |

三轮最终均为「已完成」。前两轮直接观察到结束前的正文更新，第三轮首段的精确出现时刻未采到。点击到服务端写入收件记录约 9.8–10.5 秒。三轮模型调用前，服务端等待钩子分别耗时约 5.0、5.0、13.1 秒，各轮会话锁等待均小于 3 毫秒。模型调用的首 token 与界面首段的计时起点不同。此前一次失败请求记录了约 788.5 秒的模型请求前置钩子和后续模型报错，未定位到该钩子内的具体插件。本轮五次请求各有一次成功的模型调用，未修改服务端全局配置。

## 历史、凭据和 Launcher

- 逐条比对迁移前备份，4 个旧会话中的 8 条原始问答均保留。另与升级前快照比对，其中 5 个会话的 22 条既有记录内容及顺序均保持一致。本轮增加的 3 条文本和 2 条图片记录依次显示为「已完成」。
- 第一次完全退出后，从安装目录重新打开，原问题与回答在自动认证前即可查看。密码框留空，客户端自动验证并成功发送第二条。在 Launcher 实例停机期间仍可查看已有对话。
- 确认没有待完成的受控请求后，从 Launcher 正常重启同一实例。实际回环端口由 `21056` 变为 `19087`。客户端凭实例身份自动找到新地址并恢复连接，沿用原服务端会话，第三轮仍答出前文内容。
- 两张图发送后再次完全退出再打开，整个历史文件的 SHA-256 在重开前后相同。选中会话保留 20 条记录，两条旧的「上次回复未确认」状态保持不变。本轮服务端各有五条收件和回复。
- 本机复用已有的 Windows 当前用户 DPAPI 凭据。Launcher 配置绑定实例身份，HTTPS 配置按服务地址保存，无法核实身份的手动回环 HTTP 仅在窗口内使用输入的 Key。用户可从密码框替换 Key 并验证，或点「清除」删除已保存的 Key。当前 Windows CI 用两组隔离测试凭据实际覆盖了重建存储对象后解密、更新单个配置、清除单个配置及落盘文件不含明文测试 Key。历史文件和迁移备份包含消息明文。

## 升级及权限限制

- 0.1.3 从旧安装升级时，安装器跳过了版本较高的旧运行时文件，随后移除了这些文件，造成 18 个 DLL 缺失，其中包括 `jvm.dll`。该候选已停止发布。0.1.4 会在升级时复制随包运行时。CI 复现了旧 JVM 组件版本高于新包的情况，实机另完成了从已修复的 0.1.3 升级和启动。
- 0.1.1 旧卸载器可能递归清理共享安装目录，0.1.4 保留升级保护。安装目录内有源码或其他资料时，应先按维护说明处理。[0.1.1 安全升级说明](https://github.com/Polarzen/chatbox/blob/main/desktop/README.md#从-011-升级)
- 文字需 OpenAPI `chat` 权限，图片另需 `file` 权限。0.1.2 安装版实测中，只有 `chat` 的 Key 在上传阶段收到 403，消息提示缺少 `file`，验证新 Key 后在原消息上重试成功。0.1.4 的隔离回归测试确认上传被拒后不会再提交聊天请求，实机正向验收全程使用已授权的 `chat`、`file` 凭据。
