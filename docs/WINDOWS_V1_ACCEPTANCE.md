## 0.1.2 本机基线

以下结果来自本机日常启动的 0.1.2 安装版。

- 当时使用 AstrBot Launcher 管理的 AstrBot 4.29.4 和现有配置 `deepseek-v4.1-flash-1017`。完全退出并冷启动应用后，恢复 4 个会话、8 条记录。使用已保存的 Key 重新连接后仍能继续收发。Launcher 重启后端口从 `20493` 变为 `21056`，同一服务端会话 UUID 保持不变，原迁移备份仍在。
- 三轮自然语言对话中，模型记住了自造的船名，并正确计算出 23 张和 15 张票。前两轮从点击发送到本地写入完成分别约 20.22 秒和 20.14 秒。对应模型提供方调用从开始到首 token 分别约 1.24 秒和 1.85 秒，这两组时间起点不同。另一次较长回复的界面首正文出现区间为发送后 20 至 22.5 秒。20 秒采样尚无正文，22.5 秒采样时已显示部分正文但仍在等待，约 25 秒时回复完成。
- 纯 PNG 的预期是红色圆形和数字 149，带中性说明的 JPEG 的预期是蓝色三角形和数字 882。两次盲测的模型回答均与预期相符。AstrBot 分别记录了单个 `image` 组件和一条含 `plain`、`image` 的消息。两份服务端附件均可读取，SHA-256 与原图匹配。重开后仍可辨认图片记录和回答。早期仅有 `chat` 权限时，上传返回 403。更换为含 `chat` 和 `file` 权限的 Key 后，原消息重试成功。

## 后续验收

1. 在本机确认 Windows 管理员提示，使用上表 MSI 升级原目录。核对已安装版本为 0.1.3，再由日常入口打开。
2. 在原会话完成三轮普通模型对话，记录首段正文和完成时间。期间完全退出并重开，核对历史及已保存的 Key。经 Launcher 有序重启同一实例，记录实测端口和服务端会话是否延续。
3. 分别用新样本发送纯 PNG 和 JPEG 图文，核对服务端组件、模型回答及重开后的记录。
4. 同包验收通过后，将标签指向上表源码提交，原样发布 MSI、校验文件及本报告。最后从正式 Release 重新下载 MSI 并复核 SHA-256。
