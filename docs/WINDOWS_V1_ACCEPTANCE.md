# Windows 0.1.4 修复候选验收记录

## 当前状态

0.1.3 主分支 MSI 曾实际完成安装并注册应用，但默认升级失败。安装器跳过了旧目录中版本号高于 MSI 内置组件的私有 JRE 文件，随后清理了这些旧文件，最终导致 `jvm.dll` 缺失，应用无法启动。之后仅使用原 MSI 修复了原有文件。安装启动自检及实际日常主窗口均确认可运行，注册版本为 0.1.3，缓存 MSI 的 SHA-256 与原文件一致。这不改变默认升级路径失败的结论，也不代表 0.1.3 通过验收。

0.1.4 正在准备修复候选。计划让安装器强制复制应用自带的运行时文件，并在干净 Windows 测试环境中加入真实升级回归测试。目前没有可确认的 0.1.4 最终 MSI、SHA-256、CI 或实机升级结果。正式发布前必须完成端到端升级、确认运行时文件存在并实际启动应用。

## 0.1.2 历史本机基线

以下 0.1.2 观察仍是有效基线，不代表 0.1.3 或 0.1.4 已通过：

- 测试使用 AstrBot Launcher 管理的 AstrBot 4.29.4 和现有配置 `deepseek-v4.1-flash-1017`。完全退出并冷启动后恢复 4 个会话、8 条记录，使用已保存的 Key 继续收发。Launcher 重启后端口从 `20493` 变为 `21056`，同一服务端会话 UUID 保持不变，原迁移备份仍在。
- 三轮自然语言对话中，模型记住了自造的船名，并正确计算出 23 张和 15 张票。前两轮从点击发送到本地写入完成分别约 20.22 秒和 20.14 秒。对应模型提供方调用从开始到首 token 分别约 1.24 秒和 1.85 秒，这两组时间起点不同。另一次较长回复的界面首正文出现在发送后 20 至 22.5 秒之间。20 秒采样尚无正文，22.5 秒采样时已有部分正文但仍在等待，约 25 秒时回复完成。
- 两张盲测图片均得到预期回答：纯 PNG 为红色圆形、149，带中性说明的 JPEG 为蓝色三角形、882。AstrBot 分别记录了单个 `image` 组件，以及同一条消息中的 `plain` 和 `image` 组件。两份服务端附件可读取，SHA-256 均与原图匹配。仅有 `chat` 权限时发图实际返回 403，补足 `file` 权限后可对原消息逐条重试。

## 0.1.4 正式发布条件

对最终 MSI 记录源码版本、文件大小和 SHA-256，并保留对应 CI 结果。还需在干净 Windows 测试环境中执行真实升级，确认安装器复制了应用自带的 JRE 文件，`jvm.dll` 存在，应用能从安装后的入口启动。升级后还要验证多轮文字对话和上下文、关闭重开后的历史与 Key、Launcher 端口变化后的原会话延续，以及 PNG 和 JPEG 图文发送、服务端组件、模型回答和重开后的记录。只有这些端到端结果确认后，才可将 0.1.4 标为正式版并从 [GitHub Releases](https://github.com/Polarzen/chatbox/releases) 提供下载。
