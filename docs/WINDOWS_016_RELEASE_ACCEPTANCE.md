## 正式版原目录升级

1. Windows Installer 在独立运行器上安装了正式发布的 0.1.5。旧 MSI 的 SHA-256 为 `e5f0508d74c6e90f1863cda41953c53548ef137d7a4a2725b99cbb4efdf48856`。
2. 测试夹具准备了两份服务配置、旧格式会话、回复图片引用，以及同一 Windows 用户的单把 DPAPI 测试凭据。已安装的 0.1.5 从正常入口启动，用该凭据向隔离服务完成会话查询。旧版数据由夹具预置，尚未在旧版窗口中手工创建这些记录。
3. 将候选 MSI 安装到同一目录。Windows Installer 登记了新产品，旧产品被替换。通过安装的开始菜单快捷方式连续启动两次，服务均接受了原凭据。两组会话和图片引用保留，迁移后的活动 Key 只有一条「原有密钥」。
4. 托管运行器的 Windows UI 自动化接口未能执行图文发送，升级后的夹具统计为 POST chat 0 次、POST file 0 次。本地鼠标验收及联机结果另列。

日常机器已装另一份同版本 0.1.6 预发布程序，其 ProductCode 与最终 MSI 不同，升级表排除了相同版本。Windows Installer 移除旧注册产品时要求管理员权限（1730）。随后的一次正常 UAC 提示返回取消（1223），旧产品仍注册，原 EXE 哈希保持不变。下述日常 AstrBot 请求从最终 MSI 的应用载荷发出；独立 Windows 的开始菜单验收使用了实际安装版。

## 源码与隔离服务

最终 CI 发现 52 个桌面测试，46 个执行通过，6 个需要本地界面夹具。Windows 冒烟测试、MSI 解包启动、旧运行时升级回归和 Android 共用传输代码回归通过。新增的混合有效／无效 Windows 文件名和全无效文件名测试均通过。本机另用最终提交、JDK 17、真实 Compose 桌面界面和隔离 HTTPS 服务运行这 6 项用例，6 项全部通过，无跳过，耗时 81.304 秒。

- **列表与删除**。用 44 个同名会话检查中部点击时的可见行、排列、正文和草稿。延迟请求过程中删除发起会话，原位置相邻会话按预期接替。迟到回调不重建历史。存储测试另覆盖旧排序迁移、保存失败回滚、离线记录、删除最后一条及重启为空。
- **发送与失败**。夹具分别延迟响应头、延迟首段、在部分正文后中断 SSE、在图片上传时返回 503。界面用例检查对应气泡的阶段文字和计时、保留部分正文、上传失败后不发起聊天请求，以及输入栏恢复可用。
- **凭据与图片**。测试在两个配置之间切换命名 Key，检验候选 Key 验证失败后的活动项及重启恢复。通过原有选图窗口选择 PNG、JPEG。传输测试验证多图按顺序上传并进入同一个聊天请求。

### 首个带计时的候选包

在日常 Launcher 上，从 MSI 应用载荷打开独立的测试配置，使用已保存的「测试」密钥发送普通文字。应用记录相对点击时刻的单调时钟，单位为毫秒。测试期间在输入框写入了另一条草稿，等待中的请求完成后草稿仍在。

| 场景 | 点击 | 发起聊天 | 响应头及回复流建立 | 首段正文 | 首次绘制 | 请求结束 |
|---|---:|---:|---:|---:|---:|---:|
| 文字，`c8b7928` | 0 | 5,466 | 5,574 | 15,957 | 15,973 | 16,329 |
| PNG 加说明，`c8b7928` | 0 | 5,503 | 5,583 | 15,511 | 15,523 | 15,899 |

文字请求的最长区间为流建立到首段正文的 **10.383 秒**。客户端收到正文后 **16 毫秒**完成首次绘制。服务端未提供能区分排队、插件或模型处理的事件。这条请求收到了非空回复，内容与测试提示关联较弱。图文请求在第 5,425 毫秒开始上传，第 5,503 毫秒完成上传，上传本身用时 **78 毫秒**。流建立到首段正文用了 **9.928 秒**，首次绘制再用 **12 毫秒**。

单独测量本机 Launcher 校验六次，旧实现逐一查询约 424–428 个进程，完整校验中位数为 **5,749.5 毫秒**。修改后先取得监听表，只向上查询本机回环监听进程的祖先，同轮共读取 19 个进程，完整校验中位数为 **358 毫秒**。两组均识别出同一个运行实例。每次发送仍重新核对端口归属、实例目录和 Dashboard。以上是本机身份校验耗时，服务端生成时间另计。

### 最终 MSI 的真实请求

在日常 Launcher 的同一服务、同一测试 Key、同一测试会话上，从最终 MSI 提取的程序发送文字。点击记为 0 毫秒，**358 毫秒发出聊天请求**，442 毫秒收到响应头并建立回复流，21,777 毫秒收到首段可显示内容，21,790 毫秒完成首次绘制，21,854 毫秒请求结束。与修复前同场景相比，点击到发出请求从 5,466 毫秒降到 **358 毫秒**。这次最长等待的 **21.335 秒**位于响应头和首段正文之间，首段到界面只用了 **13 毫秒**。气泡在等待的第 13 秒仍显示当前阶段，顶部保持「已连接」。[真实请求等待截图](windows-016/wait-first.jpg)

同一窗口通过选图按钮加入中文及空格路径下的 PNG。点击发送后，第 374 毫秒开始上传，第 436 毫秒完成上传并发起聊天，第 488 毫秒收到响应头，第 7,737 毫秒收到首段正文，第 7,751 毫秒首次绘制，第 8,033 毫秒结束。上传用了 **62 毫秒**；响应头到首段正文用了 **7.249 秒**，是这次请求最久的区间。与前一包的图文请求相比，点击到开始上传从 5,425 毫秒降到 **374 毫秒**。[选图后的待发送预览](windows-016/picker-preview.jpg)

## 打包客户端的窗口验收

在 `c8b7928` 包上，隔离服务预置了 49 个测试会话，其中两条同名。屏幕上可同时看见约八条。列表滚动后，顶部「新建会话」保持可见，当前聊天标题和内容保持原样。点击同名行末尾的菜单会显示目标名称和删除本机记录的说明；取消后条目还在，确认后对应行消失。[默认窗口](windows-016/sidebar-default.png) · [滚动中的列表](windows-016/sidebar-scroll.png) · [删除确认框](windows-016/delete-confirm.png)

截图尺寸为 988 × 754，坐标按 Windows 缩放后的逻辑像素计。默认窗口的侧栏宽约 232，右侧聊天面板宽约 753–754。两侧各留 22 后，消息行可用宽约 709–710。长助手回复的正文最多约 **580 逻辑像素**。这一数值由实测面板宽和排版约束推得，计算式为 `min(760, 0.86 × 消息行宽) − 30`，其中 30 为气泡左右内边距之和。

最终源码的生产界面另在 620 × 760 的 Compose 测试场景中运行。侧栏折叠，顶栏保留展开按钮。按同一口径，右侧面板宽 620，消息行宽 576，长助手回复正文可用宽约 **465 逻辑像素**。这张图来自测试场景的实际渲染。[620 宽测试场景截图](windows-016/source-narrow.png)
