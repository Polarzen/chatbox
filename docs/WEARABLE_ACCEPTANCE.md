# 0.1.20 手环历史查询验收记录

本轮软件验证使用合成健康记录。Polarzen 将另行在 Redmi Turbo 3、HyperOS 3 和小米手环 9 上核对真实数据。今日步数、昨晚睡眠与分期、最近运动与距离、运动心率样本这四项均待现场确认。

| 验证环境 | 实际观察 |
| --- | --- |
| 共享服务固定样例 | 83 项测试通过。覆盖增改删、双来源步数、缺少心率的运动、跨午夜睡眠、读权限、超时缓存、设备撤销、目的地删除、晚到睡眠、重复同步和并发投递。 |
| 独立 AstrBot 4.29.4、受控模型 | 在配对服务发起的普通聊天中，SSE 运行编号、插件事件和服务端在途操作匹配。同一 AstrBot 会话中绕开配对入口的另一条请求得到拒绝。 |
| 独立 AstrBot 4.29.4、本地 Qwen3 1.7B | 在默认人格中输入“今天训练完有点累，你觉得这次训练的强度适合我吗？”，模型自行查询一次 `exercise`。服务返回合成步行 600 秒、2,142 米，答复换算为约 10 分钟并报出 2,142 米。猫笑话对照没有调用健康工具。模型未查心率，仍把训练描述为“中等强度”；该判断没有数据依据。 |
| 独立 AstrBot 4.29.4、真实分钟调度 | 关闭运动提醒后，一条运动记录被查询并静默完成。打开提醒后，同一记录重复同步，电脑和手机的历史接口只返回一条相同的助手总结。晨间任务首读无记录，补入样例睡眠、重启 AstrBot 后，同一任务完成。整个后台过程未创建用户提问。 |
| Android JVM | 46 项 release 测试通过。包含 Health Connect 字段映射、来源证据、变更对账和离线修改共享授权的回归用例。Release lint 为 0 个错误、16 个警告。 |
| Android API 26 模拟器 | 从 v0.1.19 连续覆盖安装候选包和最终 APK，首次安装时间及本机使用设置保留。“设备设置 → 手环数据”可打开。系统健康共享不可用时，四项均显示“尚未同步”。 |
| Android API 36 模拟器 | 全新安装最终 APK，从手环页进入真实 Health Connect 系统授权界面。授予步数、拒绝睡眠、单独授予后台读取后，界面与系统权限一致。没有小米来源记录时，步数显示近 30 天未读到记录，最近同步时间为空。 |
| Windows | 桌面测试 184 项通过，15 项跳过。MSI 解包后的程序通过启动冒烟测试。JAR 内 13 个服务模块与源码逐字节相同。静态检查确认 0.1.19 → 0.1.20 的升级匹配；用户已安装的 Windows 环境升级待验。 |

共享服务可运行 `python -B -m unittest discover -s shared_service/tests`。在安装了 AstrBot 4.29.4 的隔离 Python 环境中，可运行 `python -B integrations/tests/test_chatbox_wearable.py -v` 验证插件注册、参数、权限和调度。该插件测试中的模型和健康记录均为固定样例。

实机验收时，任选一项可与小米运动健康对照的真实历史指标，记录同一指标在聊天、无新消息的任务和提醒开关两种状态下的结果。HyperOS 锁屏调度时间、两端实际显示、键盘以及蓝牙实时心率回归另记。[逐项检查和计时表](WEARABLE_GUIDE.md)
