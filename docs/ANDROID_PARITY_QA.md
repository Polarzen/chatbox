# Chatbox 0.1.17 初验 · 瑶

候选包使用 Android debug 签名，应用 ID 为 `dev.polarzen.chatbox`，versionCode 为 17，最低 Android 8.0。先核对交付目录中的 `SHA256SUMS.txt`。在安装包目录中运行以下命令，核对结果，再替换为自己的测试设备序列号。

```powershell
Get-FileHash -Algorithm SHA256 .\Chatbox-0.1.17-debug.apk
adb devices -l
adb -s <测试设备序列号> install -r .\Chatbox-0.1.17-debug.apk
```

可在手机文件管理器中点 APK 安装。覆盖升级需同应用 ID、兼容版本号和相同签名；出现 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 时保留原安装与数据，改用匹配原签名的构建或另一台测试设备。Windows 先退出 Chatbox，在原目录安装同批 MSI。无需替换 Launcher 配置。

交付 APK 的 SHA-256 完整值为 `836036836c0f526d18990d2b2e0f60bfe12bdbf3afdf7b7fb3f8a4eb6ce9ebac`。为瑶准备的 Redmi 文件位于「文件管理 → 下载 → Chatbox-0.1.17-QA-83603683.apk」。

## 准备测试会话

1. 服务管理员创建独立测试 Key。文字聊天选 `chat`，图片和 WAV 同时选 `file`。准备第二把可撤销的测试 Key 以及独立测试服务 B。密钥在设备上直接输入。
2. 让手机访问证书受信任的 AstrBot HTTPS 基础地址。若使用反向代理，可仅将 `POST /api/v1/chat`、`GET /api/v1/chat/sessions` 和 `GET/POST /api/v1/file` 转发到 AstrBot，限制在测试网络内。管理面板仍由管理员在电脑上访问。命名 Key 的验证只查询会话列表，获得文件操作权限需用实际上传和下载确认。
3. 跨端另需交付目录里的 `shared-service.zip`。按其中指南在电脑配置 AstrBot、启动个人共享服务和 Caddy，手机填写可达的 HTTPS 共享地址。PC 的回环地址只供 PC 使用。创建码、一次性加入码按需生成。生产密钥、配对码、真实聊天和设备标识均不必附在反馈中。

## 最短操作清单

| 顺序 | 从正常入口操作 | 记录结果 |
| --- | --- | --- |
| 1 | 「连接设置」保存服务 A 和命名 Key，验证后新建会话，发一条文字。 | 流式回复、密钥显示名称、首条标题。 |
| 2 | 点输入区 ＋ 选择两张图片，录一段 WAV 后停止、试听。移除一张，切换会话再返回，发送图文和语音。 | 草稿归属、上传、回复图片打开、WAV 播放。用不同命名 Key 验证无 file 权限时的提示。 |
| 3 | 退到后台再打开，搜索回复中的关键词，点命中结果。杀进程重开。测试切换失效 Key 后用原 Key 发文，再切服务 B。 | 原轮高亮、上次会话恢复、旧连接回退、B 的会话与密钥隔离。 |
| 4 | PC 创建共享会话，发送「本轮代号是青松47」，手机选择「加入已有会话」并追问代号。手机离线时 PC 发送两轮，然后重连。 | 两端原问答、代号、顺序和轮数；另测同文连发、并发、撤销配对。 |
| 5 | 长回复上滑并「回到最新」。测横屏、大字、软键盘、明暗主题、后台录音草稿、通知拒权及通知冷启动回跳。 | 记录出现问题的设备、系统构建、操作和屏幕状态。 |
| 6 | 心率面板先拒权，再授权扫描，选择开启心率广播的手环，连接后发送普通消息。停用或断开后再发一次。 | 记录手环型号、最新 BPM 和接收时间、命令排除、过期或停止后发送原文。 |

首轮由瑶记录设备型号、系统构建、候选文件 SHA-256、通过项及第一个失败步骤。对修改涉及的路径，瑶用新哈希复测；形成稳定版后再交 Polarzen 在 Redmi Turbo 3 上复验。
