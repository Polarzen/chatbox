## 设备协议 · 两套真实 AstrBot

临时环境在本机回环地址运行两套独立的 AstrBot 4.29.4、各自的数据库、受控模型和共享服务。测试脚本以电脑及手机身份调用设备 HTTP 接口，并核对 AstrBot 平台实际保存的用户、会话、提问、回答和顺序。四段平台会话各有 2、2、4、2 轮，共 **10 次对话生成**（A 为 6 次，B 为 4 次，另有 4 次标题生成）。

- 两个实例下使用相同用户名和会话编号的原记录可分别导入。双方接续对方的原会话后，仅原来收到测试暗号的实例能答出暗号。同一实例下的不同用户名也保留独立历史。
- 配对一次后，手机凭原设备身份看见后来新增的第三个档案。两端各自新建会话并完成首发，另一端均能读到。用不同操作编号主动发送两次同文产生两次生成。丢弃一次 HTTP 回执后按原编号重试，该轮只生成一次。
- 重启共享服务后，原绑定、操作编号及历史仍可读取。停掉 B 后，其已提交历史可读，新发送返回 HTTP 409，B 的生成次数保持不变，A 仍能继续生成。两端协议读到的轮次与四段平台历史逐条一致。

成功运行记录为 `service-e2e/run-cb42eab2b1/report.json`，交付 ZIP 中的 `docs/evidence/qa/fixture-results.json` 收录脱敏计数。这组调用由脚本经回环接口发起。

## 全新安装与覆盖升级的双向同步

两轮界面验收各自使用隔离的 Windows 档案、Android API 26 模拟器和两套真实 AstrBot。手机通过回环 HTTPS 和 ADB 转发访问电脑。两台设备均从普通聊天列表和输入框操作。

| 场景 | 配对与原记录 | 新建、续聊及对账 |
| --- | --- | --- |
| 全新安装 | 手机提交一次范围确认。首次出现电脑两段旧会话和手机一段旧会话。同名会话分别保留，Android 续聊原 Windows 会话答出「青松47」。 | 配对后手机新增档案 B 和会话，电脑能读到。电脑续聊手机原会话时，手机上未发送的草稿仍在。最终 4 个来源档案、4 段会话、7 轮。两套 AstrBot 的原用户名、会话编号和已保存问答均已核对。 |
| 保留 0.1.18 数据升级 | 扩大范围前设备级配对提交数为 0。电脑与手机各确认一次，手机提交 1 次。原房间、档案、授权和首轮编号保留。 | 两端分别新建会话，另一端均从普通列表续聊。3 个档案、5 段会话、8 轮，对应 8 次模型对话调用。未发送的空会话进入共享目录的数量为 0。 |

全新安装的模拟器更换 HTTPS 入口后沿用原授权。断开转发并冷启动时能阅读缓存。电脑在断线期间发出一轮，恢复转发后，已打开的手机会话自动出现该轮，计数为 1。升级场景另测电脑离线时主动发送两次相同文字，重连后每条沿用各自的操作编号，各调用模型一次，发送队列清零。

分发 APK 另做了一次 Android 系统重启。模拟器启动计数从 2 增至 3，内核启动标识改变。恢复测试用的 ADB HTTPS 转发并手动打开应用后，原配对自动恢复，原测试会话仍有旧问答。另一个仅缓存目录的电脑会话打开后，从 0 轮正文补齐至 1 轮，提问、回答、轮次编号及状态均与服务端一致。全程电脑和手机各有 1 份有效设备授权，服务端总轮数保持 12。

Windows 原生输入框接受拖入的 PNG。已授权文件上传的 AstrBot 保存了与本机原件摘要相同的文件。电脑重开后仍显示图片预览和「打开原图」，本机可解码原件。该轮手机协议读回图片和语音提示。模拟器的旧本机 WAV 已验证播放状态切换，实际音质未测。

## 从电脑撤销手机授权

升级模拟器覆盖安装提交 `3f00454` 的同签名 APK 后，Windows 从设置撤销一次。手机再次联系服务，原有的 6 条目录和 11 条正文缓存清零。用户在跨设备会话里尚未发送的文字回到一份独立本机草稿，重开应用后仍只有一份。原生聊天、旧草稿图片和 WAV 均保留，原图片可打开，WAV 播放状态可切换。服务器中查不到该未发送文字。

旧单房间和单档案授权仍可读各自旧问答。用这两种凭据访问原接口分别返回 HTTP 200，访问新版设备目录均返回 HTTP 401。档案 A 的旧入口未显示档案 B 的会话。旧入口的预计数可能滞后。Windows 切换到设备同步后，旧发布器停止更新预计数，同一档案从一段增至四段时仍显示「已收到 4 个会话，预计 1 个」。已核对四段的导入轮数均等于总轮数，原问答、档案和会话编号均保留。

## Android 大字号、横屏和草稿

API 26 模拟器在 1.5 倍字号下，从系统文件选择器添加 PNG 并输入 480 字符，竖屏及横屏展开键盘。附件、麦克风和发送按钮的触控区域均为 48×48 dp。发送按钮底边距键盘顶部，横屏 19 px、竖屏 46 px。切换会话和 Home 返回后文字与同一图片均保留。横屏再追加七个字符，点发送后本机历史中是完整的 487 字符和原图，草稿已清空。该模拟器在麦克风权限对话框触发系统界面崩溃，本次只确认录音按钮可点及应用能处理未获得权限的结果。

同一会话里，键盘开着切换会话再返回，早期候选的旧消息先后偏移 163 px（空草稿）和 188 px（图文草稿）。聊天使用倒序列表，原来只保存距底部的偏移。返回时键盘、提示栏及缩略图会先后改变可阅读的高度。修复后按消息标识恢复，并在实际高度变化时补偿滚动位置。在线复测时，空草稿的同一段文字在展开、切换返回、再展开四个时点始终位于 y=230，图文草稿始终位于 y=217。键盘先收起再切换时，图文对照同为 y=217。离线缓存的三组对照也都是 0 px。原本在底部的会话继续随键盘贴底，末条回复的语音标签距编辑框始终为 80 px。

## Windows 窗口退出与登录自启

正常关闭隔离的 Windows 窗口后，手机 HTTPS 入口仍可读取已同步的 6 段会话。重新打开窗口时服务进程及设备凭据均沿用。另在隔离 Startup 目录生成真实 Windows 快捷方式，通过系统 Shell 打开，验证了从零个服务进程恢复到一个。原身份、DPAPI 凭据和数据库保留，恢复前写入的问答可读。重复打开后进程号相同，关闭自启后快捷方式移除。这次运行覆盖登录快捷方式的执行及服务冷启动。日常 Windows 主机没有为此重启。

Launcher 端口变化使用模拟实例身份、监听端口及测试服务验证。新端口经原身份核对后可继续发送，未验证的旧端口没有收到原密钥。

在 Windows 分发 MSI 解包程序中重新打开已配置的设备向导，自定义网关端口自动回填 `18768`，手机 HTTPS 入口保留原端口 `19647`。原配对设备仍列在设置中，原问答和手机后来追加的回复均可读。
