# Chatbox 0.1.15 Windows 发布验收

0.1.15 正式安装版通过 A–D 验收。新配置和缺字段的旧配置均不占用 Ctrl+Alt+J；在首次附件下载结束前保存关闭提醒，迟到通知由 0.1.14 的 1 条降为 0 条。0.1.14 的托盘、全局唤起和通知定位已有安装版记录。[0.1.14 验收记录](WINDOWS_014_RELEASE_ACCEPTANCE.md)

## 0.1.14 正式安装版复现

**首次启动即占用快捷键。** 使用全新配置启动，以及使用缺少 `hotkeyEnabled` 字段的旧配置启动时，「全局快捷键」均显示开启。两次在外部程序尝试注册 Ctrl+Alt+J 均报告该键已被占用。

**保存关闭后仍收到迟到通知。** 独立回环服务让纯图片回复的 SSE 流先结束，再暂停首次附件 GET。聊天历史已写入本机，此时 Windows 通知数为 0。在安装版中关闭提醒并成功保存，切回记事本后放行下载。480 × 260 像素的 PNG 已缓存，Windows 随即显示 1 张原生通知。实际点击该通知后回到原会话第 3 轮。整轮有 1 次聊天提交、0 次上传。

## 0.1.15 原目录升级

Windows Installer 检出并移除原有的 0.1.14，在原路径 `D:\chat box` 登记安装 0.1.15，返回状态为 0。逐一比对，179 个安装文件的路径和 SHA-256 全部匹配候选 MSI 清单，67 个日常文件全部匹配升级前即时快照。已核对开始菜单快捷方式的 AUMID 为 `Polarzen.Chatbox`，URI 处理器指向原安装路径。

## 0.1.15 安装版验收

**A · 快捷键按保存值注册。** 从开始菜单打开已安装的 `D:\chat box\Chatbox.exe`。全新配置及缺少 `hotkeyEnabled` 字段的旧配置均显示快捷键关闭，外部程序成功注册 Ctrl+Alt+J，后台提醒独立默认开启。快捷键关闭时，从托盘和开始菜单均能唤回原窗口。启用并保存后，从记事本按键唤回同一窗口句柄；关闭并保存后，外部程序立即重新取得组合键。

**B、C · 延迟附件与真实 Windows 通知。** 在同一安装版中使用独立回环服务暂停首次附件 GET。下表每轮在暂停时聊天历史均已写入，附件尚未缓存，Windows 通知为 0；每轮有 1 次聊天提交、0 次上传。表中通知数是放行附件后实际观察到的新增原生通知数。

| 回复与设置 | 回复完成时的前台窗口 | 放行下载时的前台窗口 | 新通知 | 附件及点击结果 |
| --- | --- | --- | ---: | --- |
| 纯图片，保存关闭提醒 | 记事本 | 记事本 | 0 | 480 × 260 像素的 PNG 已缓存。 |
| 纯 WAV，保存关闭、再开启 | 记事本 | 记事本 | 0 | 2 秒合成 WAV 可播放，实测到 Windows 音频播放流。 |
| 新的纯图片，始终开启 | 记事本 | 记事本 | 1 | 点击后回到配置 A 的原会话 `A-home` 第 5 轮。 |
| 纯图片，始终关闭 | 记事本 | 记事本 | 0 | 图片已缓存。 |
| 纯 WAV，始终开启 | Chatbox | 记事本 | 0 | 缓存了 2 秒 WAV。 |
| 纯图片，始终开启 | 记事本 | Chatbox | 1 | 点击后回到同一配置、会话的第 8 轮。 |

首次 WAV 下载失败后手动重试，成功取得 2 秒 WAV，重试新增通知、聊天提交和上传均为 0。另一次流式文字加图片回复在流式阶段无通知，完成后恰有 1 条通知。冷启动重新打开原会话历史后，新增通知、聊天提交和上传也均为 0。

**D · 升级后保留既有选择与数据。** 在 0.1.14 分别保存启用和停用的 Ctrl+Alt+F23。原目录升级后，两份样本均保留原设置、草稿和历史。启用样本从记事本按键可唤回原窗口，外部程序无法取得该键；停用样本中外部程序可以取得。预设外观的启用样本保留深色、置顶、75% 不透明度，实测原生 alpha 值为 191。

**管理映像预验。** 正式安装前，另从候选 MSI 管理映像验证了无 `shell.json` 时外部可注册 Ctrl+Alt+J、提醒默认开启，以及保存关闭或关闭再开启后放行 PNG、WAV 均无新通知。两轮合计 2 次聊天提交、0 次上传。
