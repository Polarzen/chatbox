# 0.1.18 档案共享验收记录

**Redmi 已安装最终 APK，设备端 SHA-256 与交付件一致。Polarzen 的 A、B 两项实机验收待本人回执。**

隔离联调运行真实 AstrBot 框架，使用受控模型生成回复并统计生成次数。Windows 使用从 MSI 解包的完整客户端，Android 使用 API 26 模拟器。首次覆盖、首次配对及首次双向续聊使用早期 0.1.18 候选；最终 APK 同签名覆盖后沿用了原授权。

## A–E 场景

| 场景 | 实测环境与结果 |
| --- | --- |
| **A · 配对前的目录与正文** | 在 0.1.17 的 Windows 档案 A 准备三段旧问答，其中两段同名、正文不同。早期 Android 候选覆盖安装后只配对 A 一次。手机可找到两条同名结果，分别打开三段配对前的会话并核对原问题与完整回复。 |
| **B · 原会话双向续聊与去重** | 早期 Windows 客户端与 Android 模拟器在同一原会话各续一轮，手机追问得到能接续旧短句的回答，PC、手机、共享服务与 AstrBot 的记录一致。最终 MSI 解包客户端在原会话普通输入框完成一次问答，正文生成计数从 8 增至 9。主动发送两次相同文字保留两个不同轮次编号，重新同步保持两轮。 |
| **C · 新增、改名与同步恢复** | 最终 APK 沿用原配对，能看到 PC 新建的第四段会话及其新标题。模拟器离线期间 PC 在该段发送两轮，重连后编号、内容、顺序一致。再刷新两次、杀进程重启一次，历史仍一致，未再次配对。受控服务另验 10,005 轮跨页读取、分批导入中断后续传、并发发送及响应丢失后的幂等重试。 |
| **D · 旧权限、档案隔离、撤权与升级保留** | 旧单会话凭据读取原房间返回 200，访问档案目录、正文和设备管理均返回 401。仅向手机授权 A，切换 PC 档案后仍可发布 A，B 的独立记录未进入 A 的目录。Windows 撤权后，最终 APK 联网清除该档案的授权、会话和轮次缓存，三项从 1、4、8 条降至 0、0、0 条。覆盖升级保留的手机旧草稿和原单会话共享仍可打开。 |
| **E · 分层测试与真实客户端** | Android 单元及设备测试、Windows 测试及冒烟检查、共享服务测试结果见下表。Windows 完整客户端与 Android 模拟器接入隔离的真实 AstrBot 框架，使用受控模型完成原会话续聊。Redmi 已核对最终 APK 的安装哈希，Polarzen 的 A/B 操作待本人确认。 |

## 自动化与覆盖范围

| 检查 | 本次结果 |
| --- | --- |
| Android | 23 项测试全部通过。API 26 上的历史迁移与 PC 档案历史两项 instrumentation 均通过。 |
| Windows | 183 项中 167 项通过、16 项跳过。跳过项为 14 项需专用桌面 UI 环境的验收、1 项前台窗口焦点测试和 1 项需音频输出设备的 WAV 播放测试。桌面冒烟测试和 MSI 打包通过。档案面板测试验证了在原 PC 恢复主人授权。 |
| 共享服务 | 30 项 Python 测试通过，包含场景 C 的长历史、故障恢复和并发检查。 |
| Windows 安装方式 | 三版客户端先后使用同一隔离用户目录，两版 MSI 的 ProductCode 不同、UpgradeCode 相同，0.1.18 的 Upgrade 表覆盖 0.1.17 且 RemoveExistingProducts 位于 InstallInitialize 之后，系统安装器的覆盖事务仍待在隔离 Windows 环境实测。 |

旧附件在共享历史中显示已保存的类型或提示，原图与音频文件保留在原设备。PC 只剩标题，或旧正文已删除、从未保存时，手机只能看到实际发布的记录，AstrBot 会话列表无法补回缺失正文。
